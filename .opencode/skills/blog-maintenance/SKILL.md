# Blog Maintenance

Start with `AGENTS.md` at the repository root. It contains the project
invariants. This skill adds concrete workflows and verification steps.

## 1. Add or edit a post

1. Create `src/content/posts/<slug>.md`. The file path becomes the URL slug.
2. Add frontmatter:

   ```md
   ---
   title: A post title
   description: A short summary for the home page and search results.
   pubDate: 2026-11-19
   # updatedDate: 2026-11-26
   tags:
     - notes
   # draft: true
   ---
   ```

3. Start body headings at `##`. The article title is rendered separately.
4. Run `npm run check` and `npm run build`.
5. Confirm the post route, RSS item, tag pages, and sitemap updated.
6. Drafts appear in dev with a label; production excludes them from routes,
   RSS, sitemap, and Pagefind.

Do not add a second `h1` in Markdown. Do not hardcode the post URL; use
`postPath(post.id)`.

## 2. Change tag behavior or URLs

- `tagSlug()` is the only tag-to-URL function. It is Unicode-safe and uses a
  deterministic encoding; `getTagGroups()` merges any remaining slug
  collisions. Do not replace it with a simple lowercase/hyphen regex.
- `getTagGroups()` owns counts, display names, and grouped posts. Use it in
  both tag pages and the tag directory.
- In `tags/[tag].astro`, static paths must use `tag.slug` and props must use
  `tag.posts`. Never generate one path per raw tag name and filter posts inside
  the page.
- Tags are trimmed and empty tags are rejected by `content.config.ts`.
- Existing tag URLs are part of the public interface; avoid changing slugs
  unless the user requests it.

## 3. Change search behavior

- Pagefind indexes only pages with `data-pagefind-body`. `BaseLayout` adds it
  only when `indexable` is passed. Keep it on post pages and About; keep it off
  home, tag pages, Search, and 404.
- Keep the post `<h1>` as `data-pagefind-meta="title"` plus
  `data-pagefind-ignore`. Keep article metadata and tags ignored.
- `pagefind-config` must use `sitePath("pagefind/")` and `sitePath("")`.
- Verify the build log says Pagefind indexed About plus post pages only. Also
  inspect `dist/pagefind/pagefind-entry.json` (`page_count`).
- Utility pages should not appear in search results. If they do, find where
  `indexable` or `data-pagefind-body` was added.

## 4. Change the site shell, theme, or metadata

- Use `BaseLayout` props rather than writing head tags in pages:
  `title`, `description`, `ogType`, `publishedTime`, `updatedTime`, `tags`,
  `noindex`, `structuredData`.
- Site-wide values live in `src/lib/site.ts` (`SITE`). The canonical origin
  comes from `site` in `astro.config.mjs`; never reintroduce `SITE.origin`.
- Theme behavior:
  - no saved choice: follow `prefers-color-scheme`;
  - toggle: persist `light` or `dark` in `localStorage` under `stdout-theme`;
  - keep `data-theme`, `theme-color`, the icon, and the aria-label in sync.
- The active nav item uses `aria-current="page"` derived from the canonical
  path. Keep the existing section logic.
- Fonts are self-hosted through `@fontsource`. Do not add Google Fonts back.
- Preserve the current visual design unless the request explicitly changes it.

## 5. Change URLs, feeds, or crawler files

- `sitePath()` is the single path builder. `postPath()` and `tagPath()` build on
  it. Never hardcode a base path.
- `robots.txt` is generated by `src/pages/robots.txt.ts` from `site` and
  `BASE_URL`. Do not add `public/robots.txt`.
- The sitemap excludes `/search/` and `/404/` through `astro.config.mjs`.
- RSS must use `getPosts({ includeDrafts: false })`, `postPath()`, and
  `SITE.language`; it includes tags as categories.
- Canonical, Open Graph, and JSON-LD URLs must derive from `Astro.site` or
  `context.site`.

## 6. Verification checklist

Run:

```sh
npm run check
npm run build
git diff --check
```

Then inspect:

```sh
rg -n '/stdout|teef22\.github\.io|SITE\.origin|fonts\.googleapis\.com' src
cat dist/pagefind/pagefind-entry.json
cat dist/robots.txt
cat dist/sitemap-0.xml
```

Expected:

- `npm run check`: 0 errors.
- Build succeeds and Pagefind indexes About plus each published post page.
- No hardcoded base/origin or Google Fonts references under `src/`.
- `robots.txt` points at the configured sitemap.
- Sitemap includes home, About, posts, and tag pages; excludes Search and 404.
- `git diff --check` is clean.

For a base/domain safety check, build a throwaway copy with a different
`base` and `site` (for example `/test` and `https://example.com`) and verify
canonical links, Pagefind config, RSS, robots, and sitemap all follow it.

For visual changes, run `npm run preview` and inspect home, a post, tags,
Search, About, and 404. Compare against a clean build of the previous revision
when possible. The only currently accepted visual differences are the
active-nav accent and system-aware dark mode.

## 7. Common pitfalls

- Hardcoding `/stdout` in a new page or search config.
- Adding `SITE.origin` back and letting it drift from `astro.config.mjs`.
- Reimplementing `getCollection`, draft filtering, or sorting in a page.
- Building tag paths from raw names, or filtering all posts per tag.
- Adding `indexable` to a utility page, which pollutes search.
- Removing `data-pagefind-meta="title"` from the post heading.
- Reintroducing Google Fonts or external font requests.
- Editing `dist/` or `.astro/` instead of regenerating them.
- Adding `public/robots.txt` beside the generated endpoint.
- Shipping a layout/typography change while only asked to change the core.

## Definition of done

- `npm run check` and `npm run build` pass.
- Pagefind scope is correct.
- Sitemap, robots, and RSS are correct.
- No hardcoded base/origin remains under `src/`.
- The visual design is unchanged unless explicitly requested.
- `README.md` is updated if behavior or configuration changed.
